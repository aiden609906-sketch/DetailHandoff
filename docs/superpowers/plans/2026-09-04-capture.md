# Capture and Findings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement real local Before/After capture, pairing, required-slot skips and manual findings, with persisted data and guarded workflow progression.

**Architecture:** Keep the existing SwiftData JobRecord identity and add an optional encoded capture payload so existing Phase 1 records migrate without a destructive reset. Codable value records describe template slots, images and findings; JPEG files and thumbnails live under an injected private media root. A main-actor capture repository commits metadata only after file creation succeeds and restores prior state on errors. Camera and PhotosPicker feed the same repository.

**Tech Stack:** Swift 6, SwiftUI, SwiftData, UIKit camera adapter, PhotosUI, ImageIO, XCTest; iOS/iPadOS 17+.

**Spec:** `docs/superpowers/specs/2026-09-03-detailhandoff-design.md`

## Global Constraints

- Product name is `DetailHandoff`; bundle identifier `com.aiden609906.detailhandoff`.
- USD 9.99 paid download; no account, server, analytics SDK, ads, subscription, AI, or third-party runtime SDK.
- English-first, iPhone-first, adaptive iPad; iOS/iPadOS 17.0.
- Images remain private, longest side at most 2560 pixels; thumbnail at most 320 pixels; never automatically save to system Photos.
- Capture requirements and manual findings are per-job snapshots. Editing global templates must not reinterpret old jobs.
- Every data/file failure leaves existing records and files intact. Unknown/corrupt payloads produce a visible error, never silently reset to an empty record.
- Finalized/archived jobs are read-only. The later Reports plan will add an explicit revision flow.
- Camera and physical-device behavior require real-device verification; simulator CI can exercise imports, persistence and rules.

### Task 1: Durable capture document and safe media repository

**Files:** Create domain/schema and media/repository files in the map; modify JobRecord. Add schema, media and repository tests.

**Interfaces:** Produce the following public internal contracts; conform value records to Codable/Equatable/Identifiable as appropriate:

```swift
enum CapturePhase: String, Codable, CaseIterable { case before, after }
struct CaptureSlot: Codable, Equatable, Identifiable {
    var id: String
    var name: String
    var isRequired: Bool
    static var standard: [CaptureSlot] { /* literal template described below */ }
}
struct CapturedPhoto: Codable, Equatable, Identifiable {
    var id: UUID
    var slotID: String
    var phase: CapturePhase
    var imagePath: String
    var thumbnailPath: String
    var capturedAt: Date
}
struct CaptureSkip: Codable, Equatable {
    var slotID: String
    var phase: CapturePhase
    var reason: String
}
struct VehicleFinding: Codable, Equatable, Identifiable {
    var id: UUID
    var slotID: String
    var kind: String
    var severity: String
    var notes: String
    var photoIDs: [UUID]
}
struct CaptureDocument: Codable, Equatable {
    var schemaVersion: Int
    var slots: [CaptureSlot]
    var photos: [CapturedPhoto]
    var skips: [CaptureSkip]
    var findings: [VehicleFinding]
    static var empty: CaptureDocument { /* version 1 and standard slots */ }
}
// JobRecord adds: var captureData: Data? = nil
// MediaStore: init(root: URL), static defaultRoot: URL,
// storeImage(_ data: Data, jobID: UUID) throws -> StoredImage,
// url(for relativePath: String) throws -> URL,
// remove(_ image: StoredImage) throws
// StoredImage has imagePath and thumbnailPath String fields.
// CaptureRepository: @MainActor init(context: ModelContext, media: MediaStore)
// document(for job: JobRecord) throws -> CaptureDocument
// addPhoto(to job: JobRecord, data: Data, slotID: String, phase: CapturePhase) throws
// removePhoto(from job: JobRecord, photoID: UUID) throws
// setSkip(on job: JobRecord, slotID: String, phase: CapturePhase, reason: String) throws
// clearSkip(on job: JobRecord, slotID: String, phase: CapturePhase) throws
// saveFinding(on job: JobRecord, finding: VehicleFinding) throws
// removeFinding(from job: JobRecord, findingID: UUID) throws
```

Use stable IDs and names: front/Front, rear/Rear, driver-side/Driver side, passenger-side/Passenger side, front-bumper/Front bumper, rear-bumper/Rear bumper, hood-windshield/Hood and windshield, wheels-tires/Wheels and tires, front-seats/Front seats, rear-seats/Rear seats, dashboard-console/Dashboard and console, trunk/Trunk or cargo area. All 12 are required by default.

### Task 2: Guided camera/import and paired-photo screens

**Files:** Create CaptureView, CameraPicker and PhotoPairView; modify JobWorkflowView to route to capture screens in beforeCapture/afterCapture and offer read-only pair inspection. Use Task 1 interfaces unchanged.

**Interfaces:** `CaptureView(job: JobRecord, phase: CapturePhase)`, `PhotoPairView(job: JobRecord)`. Camera adapter delivers image Data or a localized error to the shared add-photo path. No new global schema.

- [ ] Add tests for pure capture presentation/selection decisions when needed, especially phase-slot pairing; hand-build two slots with disjoint Before/After photo IDs and assert each pair only contains its own slot. Do not assert source text.
- [ ] Attempt the focused XCTest command before implementation and record the actual result.
- [ ] Implement a scrollable list of all template slots, showing phase progress, thumbnails, add/import, retake/remove and skip-reason actions. Every slot allows multiple photos. PhotosPicker imports selected images without broad-library access; camera uses an authorized UIImagePickerController camera session, detects unavailable simulator hardware and denied permission, with a Settings link on denial. Camera overlay in After shows the matching Before image with adjustable opacity and does not obscure capture/cancel controls. Keep camera work isolated from data mutation; all writes go through CaptureRepository. Disable conflicting actions during import; report failed file/metadata saves without advancing state. Use a resizable Before reference on the capture screen as well.
- [ ] Pair review groups strictly by slot ID, displays all Before/After photos and skipped reasons; never guesses order-based matches. Selected full images open read-only. Avoid loading every full-resolution image into the list. Use actual thumbnails and bounded previews.
- [ ] Before camera/import, check available capacity for important usage and warn if low; failed capacity lookup must not pretend space is sufficient. Keep the check injectable for deterministic tests and expose a clear retry/cancel route on storage failures. This is a warning, not a promise that the later write cannot fail.

**Interfaces:** `FindingsView(job: JobRecord)`; `CaptureValidation.missingRequiredSlots(in: CaptureDocument, phase: CapturePhase) -> [CaptureSlot]`. CaptureRepository methods remain unchanged. JobRepositoryError adds typed incomplete-capture and corrupt-capture failures.
